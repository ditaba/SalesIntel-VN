# SalesIntel Vietnam

**B2B sales intelligence for the Vietnamese market.** It helps sales reps, agencies and IT service companies answer three questions:

1. **WHO** should I contact?
2. **WHY** should I contact this company?
3. **WHY NOW?**

```
Vietnamese companies → company data → business signals → Opportunity Score → AI analysis → prioritised prospects → recommended sales action
```

> ⚠️ **All 330 companies in this MVP are synthetic demo data.** Names, tax codes, addresses, websites, job postings and news are generated. Every demo record has a **DEMO DATA** badge (`is_demo = 1`), and its source URLs point to the reserved `example.org` domain. No external website is crawled.

This MVP is built around the *business concept* of a sales intelligence platform (in the style of SalesNow Japan). It uses none of SalesNow's branding, UI, data or code. It is a **company-intelligence** product. It does not collect personal phone numbers, personal emails or private profiles.

## Quick start

```bash
npm install
npm run build
npm start            # http://localhost:3000
```

On the first request, the app creates `data/salesintel.db` and seeds it with demo data (about 1 second). No other setup is required.

| Account | Email | Password |
|---|---|---|
| Sales rep | `demo@salesintel.vn` | `demo1234` |
| Admin | `admin@salesintel.vn` | `admin1234` |

The login page has one-click buttons for both accounts.

### Environment variables (`.env.example`)

| Variable | Purpose |
|---|---|
| `AUTH_SECRET` | Signs session cookies. **Set it in production.** |
| `ANTHROPIC_API_KEY` | *Optional.* Turns on Claude for the AI narratives and natural-language query parsing. Without it, the deterministic rules engine handles every AI feature. |
| `AI_MODEL` | Optional Claude model override (default `claude-opus-5-5`). |
| `DATABASE_PATH` | SQLite file location (default `./data/salesintel.db`). |
| `INSECURE_COOKIES=1` | Allows the session cookie over plain HTTP when running `next start` without TLS (local/demo only). |
| `DEMO_RESET_LINKS=0` | Hides the on-screen password-reset link. Set this once real email delivery exists. |

### Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Development server |
| `npm run seed` | Deletes the database and re-seeds the demo data |
| `npm test` | Unit tests: signal engine, scoring, NL parser, normalisation, CSV import, seed + search |
| `npm run e2e` | Browser end-to-end test of every major flow against a running server (`BASE_URL`, default `http://localhost:3000`) |

### Docker

```bash
docker build -t salesintel-vn .
docker run -p 3000:3000 -e AUTH_SECRET=$(openssl rand -hex 32) -v salesintel-data:/app/data salesintel-vn
```

This runs on any container host with a persistent volume (Fly.io, Render, Railway, a VPS). Serverless platforms with read-only or ephemeral filesystems need the PostgreSQL migration described in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### End-to-end demo scenario

1. Log in as the demo sales rep and open **AI Search**.
2. Ask *"Find salons in Ho Chi Minh City that may need a new website."*
3. The interpreted filters are `Industry = Beauty / Salon · Location = Ho Chi Minh City · Website = none OR weak`, sorted by score.
4. Results: **Beauty House 95**, **Hair Studio ABC 89**, **Luxury Salon XYZ 82**, then lower-scoring salons.
5. Open **Beauty House**. WHY NOW says it opened its third branch, is hiring sales and marketing staff, and its website scores 31/100 and is not mobile-friendly. Recommended services: mobile-first website redesign, online booking system, local SEO, Google Business Profile optimisation.

### Opportunity Score rules (`rules-v1`)

| Rule | Points |
|---|---|
| No website | +20 |
| Poor website quality (< 35/100) | +15 |
| Below-average website quality (35–49/100) | +10 |
| New branch / location opened | +20 |
| Hiring sales staff | +15 |
| Hiring marketing staff | +15 |
| Recent expansion | +10 |
| Strong recruitment activity (5+ open positions) | +10 |
| Moderate recruitment activity (3–4 open positions) | +5 |
| Recent company news (last 90 days) | +5 |
| Weak digital presence | +5 |
| Signal in the last 14 days / 15–30 days | +5 / +3 |

`score = min(100, round(raw × 100 / 95))`. Levels: **HIGH ≥ 70**, **MEDIUM 40–69**, **LOW < 40**.

- The website rules are mutually exclusive, and so are the recruitment rules and the recency rules.
- Signals older than 180 days stop counting.
- Each calculation is stored in `opportunity_scores` with the rule breakdown, for audit.

### FACT vs INFERENCE

Every analysis stores two lists:

- `ai_facts`: verifiable statements, each tied to a dated signal or profile field.
- `ai_inferences`: hedged interpretations ("may", "likely", "suggests").

The company page shows them side by side with different styling. Claude receives only the verified facts and the score breakdown. The prompt forbids inventing facts or changing the score. Claude may rewrite only the narrative fields.

## Tech stack

- **Next.js 15** (App Router, server components, route handlers), **React 19**, **TypeScript**, **Tailwind CSS**, Recharts, lucide icons
- **SQLite** through `better-sqlite3`, with **FTS5** full-text search. The schema is written to port directly to PostgreSQL.
- **Auth**: bcrypt password hashes, HS256 JWT in an httpOnly cookie (`jose`), edge middleware for route protection and admin gating
- **AI**: Anthropic SDK (`@anthropic-ai/sdk`) with structured JSON outputs. Optional; there is a deterministic fallback.

See **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** for the architecture, database schema, ingestion pipeline and the search scaling plan (SQLite FTS5 → PostgreSQL full-text search → OpenSearch).

## Known limitations

- The data is synthetic. No public source is connected yet. All "real" sources are registered in Admin → Data Sources as *disabled / pending review*.
- SQLite runs as a single node. That is fine for an MVP and up to roughly 100K companies, but horizontal scaling needs PostgreSQL.
- Password reset has no email delivery; the link is shown on screen in demo mode.
- No rate limiting, CSRF tokens (the app relies on SameSite=Lax cookies) or audit log of admin actions yet.
- Without `ANTHROPIC_API_KEY`, narratives come from templates. They are accurate but repetitive. With a key, "Regenerate AI analysis" rewrites them with Claude.
- Lead lists are per user; there are no team workspaces yet.
- The UI is in English, with Vietnamese company data. Vietnamese localisation is not done.

## Phase 2 recommendations

1. **Real data, compliantly.** Start with the National Business Registration Portal (via official data products or partners), publisher RSS feeds, and job boards that offer APIs or feeds. Each goes through the legal and robots review flow that already exists. Add homepage-only website scans (Lighthouse) that respect robots.txt.
2. **PostgreSQL + background jobs.** Move to Postgres with `tsvector` search and a queue (BullMQ or pg-boss) for crawling → `raw_observations` → signal engine → scoring.
3. **ICP-specific scoring.** Allow per-workspace weightings. A recruitment agency weights hiring signals higher than website quality. Learn the weights from won/lost outcomes.
4. **CRM sync** (HubSpot, Salesforce, Zoho, Base.vn), Slack/Zalo alerts for new high-score signals, and saved-search alerts.
5. **Teams and billing**: workspaces, seats, usage limits, audit log, SSO.
6. **Vietnamese UI** and Vietnamese-language AI pitches.
7. **Better entity resolution** (tax code + fuzzy name/address matching) as more sources are merged.
